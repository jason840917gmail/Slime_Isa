How a sample is decided

The map already supplies one logical tile for each cell. Blending never changes that tile, collision, or walkability. Instead, this calculation decides how much of each nearby terrain material is visible at every sampled pixel.

  1. Warp the sample position

    u′ = u + 0.45N(0.45u, 0.45v) + 0.10N(2.2u, 2.2v)
    v′ = v + 0.45N′(0.45u, 0.45v) + 0.10N′(2.2u, 2.2v)

    Deterministic value noise moves the lookup point away from the rigid grid. The same map and seed always produce the same wandering border.

  2. Collect votes from nearby tiles

    k(d) = (1 − d²/R²)² when d < R, otherwise 0
    Wm = Σ k(dcell), with R = 1.05 tiles

    The 3×3 cells around the warped point vote for their material. A cell centre has the strongest vote; influence fades smoothly to zero at the kernel radius.

  3. Bias, sharpen, and normalize

    sm = [Wm · (1 + 0.14 · rankm)]⁴
    sharem = sm / Σ sj

    Priority rank nudges higher materials into lower ones. Raising the result to the fourth power makes the strongest vote dominate, while normalization turns all votes into shares that sum to 1.

  4. Turn shares into painted layers

    αm = sharem / Σj ≤ m sharej

    Materials paint from lowest to highest priority using source-over compositing. This alpha conversion makes the final pixel reproduce the calculated shares.

Decision workflow

  1. Read the sample’s logical cell and warp its position.
  2. Find the surrounding blend-enabled cells and total their votes by material.
  3. Apply rank bias and sharpness; if no tile reaches the point, use the logical cell’s material.
  4. Normalize the votes. The largest share is the visually dominant material, but every non-zero share contributes to the final blended pixel.
  5. Paint the material layers in priority order. Non-blending logical tiles are cleared back to their original hard-edged tile.

For implementation details, chunk baking, and constant names, see TERRAIN_BLEND_MATH.md.
