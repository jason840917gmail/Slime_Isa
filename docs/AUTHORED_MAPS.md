# Authored Maps

Every playable world is an authored world scene: `src/game/content/scenes/authored/worlds/<map-id>.scene.json`, scene ID `world.<map-id>`. `MapLoadScene` loads it through `WorldSceneLoader`; a missing or invalid world scene stops loading with a visible error. Worlds contain stable IDs, positions, and initial state only; image paths live in `asset/assets.json` and behavior lives in registered scripts.

## What a world scene contains

- A `game.world-definition` ScriptNode with `mapId`, `tileSize`, `columns`, `rows`, spawn/entry `metadata`, and optional `cameraMode` (`follow` by default, `fixed` for small interiors).
- A `TileMapLayer2D` painting logical terrain IDs (`grass-a`, `water`, …) from the shared `terrain.tiles` TileSet resource (`resources/terrain/terrain.tile-set.resource.json`, read through `content/terrain/TileCatalog.ts`). Its tile data is a sub-resource of the world scene. Terrain is ground only; blending is described in `docs/TERRAIN_TRANSITIONS.md`.
- Instances of reusable scenes (`object.*`, `character.*`, `encounter.*`). An instance may override properties such as position and initial state; the source scene owns art, collision, and behavior. Each instance keeps a stable `instanceId` and `persistenceKey`; do not change them when moving it. Forest and cave walls are `object.tree-forest-wall.*` / `object.crystal-cluster-wall.*` instances, not tiles.
- `Area2D` + `game.world-area` nodes (`areaKind`: `enemy-safe-zone`, `enemy-spawn`, `npc-wander`) whose perimeters are rectangle or circle collision shapes. A spawn camp's inner `stayShape` is where enemies spawn and settle; enemies that leave the outer pursue `shape` return home. Its `data` holds `enemies`, `intervalMs`, and `maxPopulation`.
- `game.world-exit` and `game.door` scripts for exits and door links; locked gates are `game.gate` object instances (e.g. `object.gate-verdant`).

## Legacy `.map.json` files

`src/game/content/maps/<map-id>.map.json` (format v1, `mapFormat.ts`) were the pre-scene source and remain conversion inputs. They are still read for the new-run spawn (`InitialRun.ts`), for validating a saved location's map and bounds (`SaveSystem` via `MapRepository`), and by `pnpm maps:check`. Scene Studio does not write them, so keep a world's `mapId`, dimensions, and spawn consistent with its `.map.json`.

`pnpm maps:bake` rewrites only `gloop-forest.map.json` and `crystal-caverns.map.json` from the deterministic generator; it does not touch world scenes. `pnpm scenes:regenerate` re-converts legacy inputs over scene-owned documents, so avoid it unless replacing authored world edits is intentional.

## Edit a world

Edit worlds in Scene Studio (`pnpm dev`, then `http://localhost:3000/?studio=scenes&scene=world.<map-id>`; the old `?editor=<map-id>` URL redirects there). Level-1 is generated by `node scripts/maps/build-level-1.mjs`; hand edits to its `gen-*` content are replaced on the next run. See `AGENTS.md` for the decoration scatter and terrain smoothing tools.

After editing, run `pnpm scenes:check`, `pnpm maps:check`, and `pnpm typecheck`.

## Preview and activate

Preview any world in development mode:

```text
http://localhost:3000/?map=test-rectangle
```

For normal area loading, set the area's `mapId` in `src/game/world/Area.ts`. `Area.ts` owns the world graph; world scenes own the physical exit zones, doors, and entry coordinates.
